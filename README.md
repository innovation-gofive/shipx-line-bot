# ShipX LINE Bot — v0.2

App ให้ลูกค้าสอบถามสถานะออเดอร์ สต๊อกตาม SKU ภาพรวมออเดอร์ และยอดขายผ่าน LINE Group พร้อมหน้าผู้ดูแลผูก LINE Group ID → ShipX Company ID และ Docker Compose สำหรับ Coolify

เริ่มทดลอง:

```powershell
cd C:\ShipX-Line-Bot
npm run demo
```

เปิด `http://localhost:3000` ผู้ใช้ `admin` รหัส demo `shipx-demo-local-2026` ต้องใช้ Node.js 24 ขึ้นไป หากยังไม่มี dependencies รัน `npm ci` ก่อน

อ่าน [วิธีอัปเกรดและทดสอบ v0.2](RELEASE_0.2.md) สำหรับขั้นตอนเปิดสิทธิ์และทดสอบใน LINE ส่วน [คู่มือเริ่มต้น](TESTING_GUIDE.md) และ [รายงาน QA เดิม](QA_REPORT.md) บันทึกการติดตั้งและทดสอบ v0.1

อ่าน [คู่มือตั้งค่าและสอน AI](AI_SETUP_GUIDE.md) สำหรับสร้าง Project/API key, ตั้งค่า Coolify, เพิ่มตัวอย่างคำถาม และทดสอบ AI สองช่วงด้วยข้อมูลจำลอง

## ขอบเขต API จากไฟล์แนบ

- V1: `GET /api/v1/Company/GetListCompany` อ่าน `data.companies[].companyId/companyName`
- V2: `GET /api/v2/Order/search` ส่ง `searchText`, `companyIds`, `pageNumber`, `pageSize` และอ่าน `data.data[]`, `data.hasMore`
- สต๊อก: `GET /api/v2/Product/variant` ตรวจบริษัทของ Product Master แล้วใช้คู่ ID สินค้าเทียบกับแถวใน `GET /api/v1/stock-analytics` ก่อนอ่านยอด
- รายงาน: `GET /api/v2/Report/daily` และ `GET /api/v2/Report/order/summary` มี `appliedCompanyIds` สำหรับตรวจบริษัทของตัวเลขรวม
- กำหนดส่งและความคืบหน้าแพ็ค: `POST /api/v3/Order/list/order-platform` กรอง ShippingDate แล้วตรวจ companyId / shippingDate ของแต่ละแถวและอ่านทุกหน้าก่อนคำนวณ ผู้ใช้ยืนยันว่า ShippingDate คือวันที่กำหนดส่ง
- เอกสารไม่ระบุ server URL; ต้องยืนยัน Base URL และวิธี authentication ก่อนใช้งานจริง ตัว client รองรับส่ง X-API-Key และ Bearer พร้อมกัน

ใน LINE ให้เลือกแท็ก `@ShipX Bot` จากรายชื่อก่อนพิมพ์ เช่น `ออเดอร์ SO001 ให้หน่อย`, `เช็กสต๊อก SKU001`, `สรุปออเดอร์ค้างวันนี้และย้อนหลัง 2 วัน` หรือ `รายงานยอดขายวันนี้` ในหน้าทดสอบ Admin พิมพ์เฉพาะคำถามได้ การตอบใช้ Flex Message พร้อมข้อความภาษาไทยตามข้อมูล ShipX และตารางสถานะใน Appendix 15.1

ตั้ง `OPENAI_API_KEY` เพื่อให้ AI เรียกเครื่องมืออ่าน ShipX ที่ระบบเปิดให้ตามสิทธิ์ แล้วให้ AI ช่วงที่สองสร้างแผนการ์ดกับข้อความสรุป ระบบตรวจแผนว่าครบทุกช่องและเติมค่าจริงจาก API ก่อนส่ง LINE โดยไม่ให้ AI เปลี่ยนตัวเลขหรือขอบเขตบริษัท ตั้ง `AI_RESPONSE_ENABLED=false` ได้หากต้องการปิดเฉพาะ AI จัดคำตอบ ระบบใช้คำสั่งและการ์ดมาตรฐานได้เมื่อไม่มีคีย์หรือ AI ขัดข้อง

ข้อความลูกค้าต้องแท็ก Bot จริงจากรายการชื่อใน LINE จึงจะเริ่มประมวลผล ข้อยกเว้นคือแจ้งเตือนอัตโนมัติในกลุ่มที่เปิดใช้ ผู้ดูแลเลือกเวลาไทยได้แยกตามกลุ่ม โดยมีค่าเริ่มต้น 16:00 น. ระบบส่งเมื่อมีออเดอร์กำหนดส่งวันนั้นที่ยังแพ็คไม่เสร็จหรือยังตรวจสถานะไม่ได้ และใช้คิวถาวรกับ LINE retry key ป้องกันการแจ้งซ้ำ

ผู้ดูแลเปิด **ส่งสรุปงานที่จัดส่งรายวัน** และเลือกเวลาตัดยอดได้ในหน้าตั้งค่ากลุ่ม กลุ่มต้องเปิดใช้งานและมีสิทธิ์รายงาน ค่าเริ่มต้นคือ 18:00 น. เวลาไทย การ์ดแรกนับออเดอร์ที่สแกนส่งออกครบทุกกล่องจาก `GET /api/v2/Order/summaryPlatform/history` ตั้งแต่เที่ยงคืนถึงเวลาที่ตั้งไว้ แยกยอด B2B จาก `orderType` และแสดงจำนวน Express ที่รวมอยู่ในยอด B2B ยอดช่องทางอื่นแสดงในแถว **อื่น ๆ** เมื่อมีรายการ

การ์ดติดตามงานใช้ `ShippingDate` เป็นกำหนดส่งและอ่านสถานะล่าสุดของออเดอร์ที่ครบกำหนดวันนั้นตอนรันรอบแจ้งเตือน แยก B2C และ B2B ปุ่ม **ดูรายการออเดอร์** เปิดเลขออเดอร์และสถานะ ณ รอบแจ้งเตือนผ่านโดเมน `APP_URL` ลิงก์เปิดได้โดยผู้ที่ถือครองลิงก์และมีอายุ 24 ชั่วโมง ลิงก์เดิมถูกยกเลิกเมื่อเปลี่ยนบริษัท ปิดสิทธิ์รายงาน ปิดการสรุปรายวัน หรือบอทออกจากกลุ่ม สถานะ 2004 คือ **รอรถมารับ** และ 2003 หรือสถานะที่ยังอยู่ระหว่างเตรียมงานคือ **ยังไม่พร้อมจัดส่ง** สถานะที่ยังแปลไม่ได้จะแสดงให้ตรวจเพิ่ม รายการส่งแล้ว ยกเลิก และคืนสินค้าไม่รวมในงานค้าง ออเดอร์ที่สแกนส่งออกครบแล้วอาจยังอยู่ในยอดรอรถมารับจนกว่า ShipX จะบันทึกว่าส่งออกแล้ว ส่วนนี้เปิดเมื่อยืนยันการใช้ `ShippingDate` ผ่าน `SHIPX_SHIPPING_DATE_IS_DUE_DATE` แล้ว

## การแยกบริษัท

1. ตรวจ HMAC-SHA256 จาก raw body ของ LINE ก่อนประมวลผล
2. บันทึกกลุ่มที่ตรวจพบ โดยยังไม่เปิดสิทธิ์จนกว่า Admin จะผูกบริษัท
3. อ่าน Company ID จาก Mapping ฝั่ง server เสมอ ไม่รับ Company ID จากคำสั่งลูกค้า
4. ส่งตัวกรองบริษัทไป ShipX และตรวจ `companyId` ของแต่ละ Order ซ้ำ หากไม่มีหรือไม่ตรงจะไม่แสดง
5. ตรวจเลขอ้างอิงแบบตรงทั้งค่า ตรวจเจ้าของ SKU จาก Product Master และตรวจ `appliedCompanyIds` ของรายงานว่ามีเพียงบริษัทของกลุ่ม
6. ตรวจ Mapping และสิทธิ์ Order / สต๊อก / รายงานก่อนเรียก ShipX และตรวจซ้ำก่อนส่ง LINE ถ้าสิทธิ์เปลี่ยนจะยกเลิกข้อมูลเดิม
7. บริษัทหนึ่งเปิดใช้งานได้หนึ่งกลุ่ม; Bot ออกจากกลุ่มจะปิดสิทธิ์อัตโนมัติ

มี login ของ Admin, session cookie, CSRF token, origin check, rate limit, Audit log และ durable webhook inbox ที่ deduplicate ด้วย webhookEventId

## การใช้งานจริง

ตั้งค่าตาม `.env.example` แล้ว `npm start` หรือ deploy ด้วย `docker-compose.yml` ตามคู่มือ ห้าม commit `.env` หรือฐานข้อมูล

- App รันที่ port 3000; health endpoint `/healthz`; LINE endpoint `/webhook`
- SQLite เก็บที่ `/app/data/shipx.sqlite` ใน production ต้องคง volume `shipx-data` และรัน App หนึ่ง replica หลีกเลี่ยงการรัน container สองตัวบนไฟล์เดียวกันพร้อมกัน
- Demo ใช้ `data/demo.sqlite` หรือ `DEMO_DATABASE_PATH` แยกจาก `DATABASE_PATH` ของระบบจริงเสมอ ไม่ตั้งสองค่านี้เป็นไฟล์เดียวกัน
- สำรองข้อมูลโดยหยุด App แล้วสำรองทั้ง volume ก่อนเปิด App ต่อ ห้ามลบ volume เมื่อ redeploy
- session หมดอายุ 8 ชั่วโมงและถูกล้างเมื่อ server restart
- Audit เก็บ 90 วัน; event ID สำหรับ dedup เก็บ 7 วัน; payload/replyToken ถูกล้างเมื่อประมวลผลเสร็จ
- รับ webhook แล้วตอบ 200 หลัง commit inbox งานประมวลผลภายหลัง ข้อมูลสถานะไม่ถูกเก็บเป็น cache
- งานตอบคำถาม LINE ที่ไม่สำเร็จบันทึก failed ผู้ใช้ส่งคำสั่งใหม่ได้ ส่วนงานแจ้งเตือนอัตโนมัติส่งซ้ำเฉพาะเมื่อเครือข่ายหรือ LINE 5xx ขัดข้อง สูงสุด 3 ครั้งด้วยข้อความและ retry key เดิม ตรวจ Audit ในกรณีผิดพลาด
- คิวทำงานตามลำดับและมีเวลาจำกัดของ LINE reply token
- สมาชิกทุกคนใน LINE Group มีสิทธิ์บริษัทเดียวกัน ต้องควบคุมสมาชิกกลุ่มด้วย
